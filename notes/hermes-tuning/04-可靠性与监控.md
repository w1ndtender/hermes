# 04 可靠性：静默失败是头号杀手

## 别人的教训
一家公司在生产跑一个月：4 个 agent、36 个 cron，出现过**六天静默停机**。
四条硬结论：
1. 容器/服务必须以正确模式常驻，否则开机即退。
2. 每个 agent 独立容器与 UID，否则凭据隔离是假的。
3. **每个 cron 必须钉模型**，否则供应商一换就静默死。
4. **每个静默失败都要有计数器**。

## 我们身上的实例
- `agent-daily-brief` 上次 **idle 7943 秒后超时失败**，错误只在 cron 历史里。
- 抓数据的脚本里 `except: pass` 把接口失败当「没有数据」。

## 做法
- 每任务写一行结构化日志：`{任务, 时间, 成功/失败, 条数, 耗时}`。
- 一天一条汇总；**只有异常才推**。
- 用 `hermes cron doctor` / `incidents` 定期看一眼。
- 超时设置要显式给，不要靠默认值。
