# 22 插件怎么写、技能怎么工程化（看真代码，不是看介绍）

## 一、真实插件长什么样（GitHub: zhaotui/hermes-xhs-ops）

目录：
```
plugin.yaml      # 清单
__init__.py      # register(ctx)
tools.py         # 五万字节，所有工具实现
client.py        # 外部依赖封装
skills/ scripts/ deploy/ assets/
```

`plugin.yaml`（完整）：
```yaml
name: xhs
version: 1.0.0
description: "小红书运营插件 — 发帖、读评论、回评论、收集信息、删帖"
author: hermes-zr
kind: backend
provides_tools:
  - xhs_account_manager
  - xhs_publish_post
  - xhs_read_comments
  - xhs_view_note_detail
  - xhs_reply_comment
  - xhs_collect_info
  - xhs_delete_post
```

`__init__.py` 的接入口只有一个函数：
```python
def register(ctx) -> None:
    for name, schema, handler, emoji in TOOLS:
        ctx.register_tool(
            name=name, toolset="xhs", schema=schema, handler=handler,
            check_fn=_check_webbridge,   # 依赖没装好时，工具自动不可用
            emoji=emoji,
        )
```

三个可抄的点：
1. **`check_fn`**：外部依赖（这里是要在 Windows 上跑的 WebBridge）不在线时，工具直接标成不可用，而不是调用时报错。
2. **一个工具集（toolset）打包多个动作**，模型看到的是 7 个工具，不是一个万能函数。
3. **schema 与实现分离**：`TOOLS` 是一个 (name, schema, handler, emoji) 的列表。

## 二、技能怎么写才像"安装向导"（GitHub: alejandro-ao/skills/hermes-vps-setup）

这个 skill 的目标不是"教命令"，是"带一个不懂 Linux 的人走完安装"。它的写法值得抄：

- 开头先写**终态**：不 root 运行、开机自启、能被消息平台访问、有日志与健康检查、有 git 备份、不暴露密钥。
- 专门的 **Communication Requirements** 一节：
  - 每一步先说「接下来我要做什么、为什么重要」
  - 危险或不可逆步骤（改 SSH、开防火墙、禁用密码登录、建 deploy key、起 systemd 服务）**先解释风险再确认**
  - 命令跑完要总结「变了什么、接下来会发生什么」
  - 等用户操作时给**可直接照抄**的指令和示例
- 语气要求写死在 skill 里（"轻快但不幼稚"）。

**启示**：复杂流程的 skill，一半篇幅该花在"怎么说给人听"，而不是"命令是什么"。

## 三、生态里一个明显的趋势

找到的实操型 skill/插件，几乎都在解决同一件事：**目标网站没有 API，只能操控浏览器**。
- 小红书那套：CDP / WebBridge 直连，不用 API
- 还专门写了对抗方案：Chrome 147+ 自带 Gemini 助手会干扰 CDP，skill 末尾附故障排查

和我们 SafeTrade 必须走 CDP 同源 fetch 是同一个处境，结论也一样：**把浏览器当成事实上的 API，并把"环境坑 + 对抗办法"写进 skill。**

## 四、我们该改的一处

现在 `~/spread` 里的东西全是一个个 `.py` 脚本，靠记忆和文档记住用法。
真做成插件的话，形态应该是：
- `plugin.yaml` 列出 `spread_quote` / `spread_open` / `spread_close` / `spread_status` 四个工具
- `check_fn` 检查交易所连通性、账户余额、STOP 文件是否存在——不通就是"工具不可用"，不是"调用失败"
- schema 写死参数范围，越界在入口就拦掉

这条不是现在做，记下来：**工具化比脚本化安全，因为参数范围可以被 schema 约束，而不是靠调用方自觉。**
