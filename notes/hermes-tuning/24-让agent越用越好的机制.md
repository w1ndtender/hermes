# 24 让 agent 越用越好：双层循环（这是"他们做到了"的机制）

## 核心：两个循环，不是一个

Warp 那篇（2026-06-16，Zach Lloyd）把自我改进拆成两层：

- **内层循环**：agent 真正干活的循环。每跑一次，**把这次运行留痕**（输入、用的 skill、输出、人要没要返工、错在哪）。
- **外层循环**：一个按计划跑的 agent，**只读那些留痕**，判断 skill 哪里不够，然后**对 skill 文件做最小 diff**。

关键前提一句话：**skill 就是文件，所以"改进"= 一次可审阅的 diff**。没有留痕，外层循环无从下手；没有 diff，就只是"又聊了一轮"。

## 我们为什么没做到

别人的形状是：`干活 → 留痕 → 定时审痕 → 改 skill（diff）→ 下次直接生效`。
我的形状一直是：`干活 → 聊天里总结 → 写一篇笔记 → 没人读`。

三个缺口：
1. **没有留痕**：每次任务的结果只活在聊天记录里，外层循环拿不到结构化输入。
2. **改的不是可执行物**：我改的是笔记和记忆（越加越长），不是 skill 里的那条命令/判断。
3. **没有回滚与对照**：改完不知道变好还是变坏，因为没有用例集（今天刚建了 20 条）。

## 外层循环的四条纪律（缺一条就会变成"瞎改"）

1. **只改有证据的**：同一类错出现 **≥2 次** 才动 skill；一次可能只是任务特殊。
2. **一次只改一处**，diff 要小到能一眼看完。
3. **必须写理由 + 证据**（哪几次运行、什么症状），写进 commit message。
4. **改完要能回滚**：文件在 git 里，改前 `git commit`，改坏 `git revert`。

## 上下文工程那条铁律（Anthropic）

- 系统提示要**在高信号层面**：说"什么算做对了"，不是把每一步都写死。
- 上下文只放**最小的高信号集合**；细节靠 skill/文件按需加载。
- 长任务用**结构化笔记**（进度、决定、待办）代替"记住对话"。

→ 对应我们的问题：SOUL 别写流程，流程进 skill；memory 别放事实，事实进 `env-facts.md`。
