# 20 真实使用案例（官方 User Stories 112 条里挑出来的）

来源：`hermes-agent.nousresearch.com/docs/user-stories`（社区真实帖子，X/Reddit/HN/YouTube 链接可点）。

## 一、跟我们最像的四种用法

### 1. 「多条信号 + 一个日账本 + 一个 agent 做研判」
> “20 来个『信号』（纯 cron 跑的 skill），全都往一个日账本里写格式化日志；
> 再用一个 agent 型 cron 去审这批日志，把重要的挑进一个『研判账本』。”

这就是我们该有的形状：**抓取全部无脑写日志（零 token），研判单独一小时一次（花 token 但值）。**

### 2. 夜间「做梦」：把当天全部对话炼成第二天的上下文
> “28 个 cron、30+ 自建 skill。每天凌晨 3 点，它读我们当天所有对话，
> 提取做过的决定、推进的项目、查过的 bug、聊过的人、不该再犯的错。”

比我们想的「0 点日报」更进一步：**不是汇报，是提炼成第二天能直接用的一页纸。**

### 3. 零 token 的 cron 模式
> “`--script --no-agent`：脚本就是任务本身。没有 agent 循环，没有 LLM 调用。”

### 4. 每天一个固定产出 + 人工批准
> SEO 那位：“每天看分析数据、找机会、写内容，**等我批准**，我同意它就发布。”
> 外呼那位：“研究完账号，把每一条发送都排队等我在 Telegram 里批。”

## 二、值得知道的其它做法（按行业）

| 场景 | 做法 | 一句话结论 |
|---|---|---|
| 施工方 | 11 个 WhatsApp 群、82 条消息 → **3 行摘要** | 摘要的价值在于「压缩到能读完」 |
| 小商家 | 客户邮件 → 直接生成 Shopify 草稿订单，等人复核 | 生成草稿不算动作，发送才算 |
| 律所/地产 | 付款对账自动核 | 只读+比对，不自动付款 |
| 咨询 | 接自建 CRM，出一份 8 页会议准备简报 | 「准备材料」比「回答问题」值钱 |
| IT 运维 | 165 人公司把 80% 日常工作搬进来 | 单人运维的天花板在于审批闸 |
| 内容 | LinkedIn 外呼：研究账号→排队等批准→发 | 对外动作一律排队 |
| 研究 | 3799 页手册解析进 SQLite FTS5，不进向量库 | 大材料落库，别塞上下文 |
| 小成本部署 | Hetzner €4/月 + Docker + Ansible，客户整套约 $9/月 | 成本不是障碍 |
| 安全 | 给 agent 单独一个邮箱做「守门人」，它看不到 2FA 码 | 凭据隔离靠架构，不靠自律 |
| 多客户 | 每个客户一个 profile（各自的 soul/记忆） | 我们暂时不需要 |

## 三、他们踩过、我们也踩过的

- **cron 是新会话**：不带聊天上下文，提示里必须把 URL、命令、规则全写出来。
- **`--workdir`**：不指定就跑在网关所在目录，AGENTS.md 也不会加载。
- **`[SILENT]`**：没有异常就只回这个词，消息被抑制 —— 治「天天推没用的」。
- **装了什么要留痕**：有人专门做工具追踪，「几天后就不知道这些包哪来的」。

## 四、我们的映射（五条）

1. 抓取/扫描全部改**脚本模式写日账本**；研判单独一条 agent 任务，一天 1–3 次。
2. 每天 0 点那条改成**提炼**：今天做了什么决定、哪里错了、明天要盯什么。
3. 所有对外/花钱动作排队等批准；只读与草稿可以自动。
4. 大材料（历史成交、链上事件、看板快照）落 SQLite，用查询代替重读。
5. 每次装东西/改服务，写一行到 `~/repos/hermes/notes/installs.md`，防「不知道哪来的」。
