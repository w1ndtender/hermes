# 14 协作沟通坑（中文社区实战总结）

来源：一位和 Hermes 协作两个月的作者列的 12 个坑（2026-05），挑出仍然成立的。

1. **语言**：系统提示默认英文，中文提问可能英文作答 → 第一句就说「用中文回复」，或直接说「说中文」。
2. **模糊指令会放大**：说「去掉那个圆圈」，它把圆圈画得更大。要说得可验证：
   「不要任何圆形背景，只要文字和渐变」。
3. **解释癖**：它会先长篇解释再动手。直接说「直接干」「别解释」。
4. **子任务写同一路径会互相覆盖**：并行任务必须各写各的文件。
5. **会话不持久的东西别当资产**：临时目录里的脚本会丢；要长期用的写进 skill 或 git 仓库。
6. **视觉/设计类反馈要具体**：给「零人工形状」「纯文字 + 照片」这种硬约束，别给形容词。

## 对我们最有用的一条
**指令要可验证**：不说「优化一下」，说「把 A 改成 B，验收命令是 C，输出应为 D」。
