# 10 调试与日志：症状 → 该看哪份

## 日志在哪（`~/.hermes/logs/`）
| 文件 | 内容 | 什么时候看 |
|---|---|---|
| `agent.log` | 主活动（工具、会话） | 不知道发生了什么，先 `tail -f` 这个 |
| `errors.log` | 仅告警与错误 | 崩溃、500、堆栈 |
| `gateway.log` | 网关事件（TG/Discord 用户会话生命周期） | 「它不出声了」 |
| `gui.log` | 控制台/websocket | 界面不刷新 |

## 常用命令
```
hermes logs errors --since 30m -f
hermes logs gateway --session <id>
hermes logs -f                    # agent.log
hermes cron runs <job_id>         # 每次尝试的账本
hermes cron incidents             # 持久化的失败记录
hermes cron doctor                # 只报告、不改动
```

## 会话级排查（最有用的产物）
每次会话的完整轨迹落成 JSONL：`~/.hermes/logs/sessions/<时间>.jsonl`。
一个中等会话 800 行很正常。工具 `trace-tree` 把它打印成树：会话是根，每次工具调用是子节点，
被拒绝的调用带错误信息一起显示。

**判断口诀**
- 报错但没结论 → `errors.log`
- 答得通顺但事实错 → 看那次会话的 JSONL（工具调用顺序和参数）
- 该出声却没声 → `gateway.log`
