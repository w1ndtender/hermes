# 09 安全与审批（官方八层模型）

## 八层（按从外到内）
1. 用户授权：谁能跟 agent 说话（allowlist / DM 配对）
2. 危险命令审批：人在回路
3. 文件写入安全：denylist + 可选写入沙箱
4. 容器隔离：Docker/Modal
5. MCP 凭据过滤：子进程环境变量隔离
6. 上下文文件扫描：项目文件里的 prompt injection 检测
7. 跨会话隔离：会话之间不能互读数据；cron 存储路径防穿越
8. 输入净化：工作目录参数按 allowlist 校验，防 shell 注入

## 审批配置（`~/.hermes/config.yaml`）
```yaml
approvals:
  mode: smart            # smart | manual | off
  timeout: 300
  cron_mode: deny        # 定时任务碰到危险命令：deny 就拒绝，让它另想办法
  single_query_mode: deny
  unattended_mode: deny
  destructive_slash_confirm: true
```
**重点**：`cron_mode` 默认 `deny`。谁把它改成 `approve`，等于让定时任务无人监督地跑危险命令。

## 我们的对应做法
- 钱：真实下单要 `dry_run:false` + 用户当次点头（双闸）。
- 不可逆：`STOP` 文件 + 亏损平仓先问。
- 凭据：私钥/API key 不进聊天、不写文档，`[REDACTED]` 入库。
- 定时任务里不许出现 `rm -rf`、`systemctl stop` 之类；真要停服务，用独立看门狗脚本（写成 `--script` 任务）。
