# 21 社区真实案例（Reddit / HN / 知乎 / GitHub，逐个看过原文）

## 1. rumjahn：一个用了 15 天的个人用户（r/hermesagent，2026-04-25，58 赞）

- **Telegram 按话题分线程**：不同任务不同话题，等于手动分会话。
- **记忆外置**：原来 99% 挤在热记忆里，改成「记忆以 .md 存进 NAS 上的 Obsidian 库」，**热记忆降到 56%**。
- **LLM wiki（复利）**：邮件、日历、帖子、健康数据全落到同一个库里，agent 持续读写。「和单纯聊天模型的区别是上下文会复利，第二个月明显比第一个月好。」
- **省钱**：Hermes 自带按复杂度路由（便宜模型/主模型），再叠 OpenRouter 自动路由，日常问题都落便宜档。
- 内容流程：技能起草 → 他批准 → Postiz 定时发。"我只需说想要什么，它按我的语气写，我点头，它排期。"

**能抄**：记忆分层（热记忆只留指针，事实进文件库）；按话题分线程。

## 2. chrisaumen：影视公司的"办公室"（r/hermesagent，2026-07-29）

每个角色一个 profile，各自有指令、工具、记忆、权限：

| Agent | 职责 |
|---|---|
| Alfred | 前台，把一条语音便签分派到项目/agent/日历 |
| Danny | 制片：预算、通告、把拍花的日程照片转成电子版、发票 |
| George | 销售：每个工作日上午查提案状态，未签的起草跟进 |
| Truman | 内容：读通话记录和时间日志，找选题进审核队列 |
| Harriet / Q | 研究 / 运维：Q 跑一堆 watchdog cron，还负责修别的 agent |

- **共享 Obsidian 的"事实文件"**（怎么干活、有什么设备、规则、报价）。原话：**「这份共享上下文比选哪个模型更重要。」**
- **权限阶梯**：只读 → 草稿 → 审批队列；发送、删除、花钱、签字永远留给人。
- **文档绑定批准码**：电子签名必须先拿到与"他看过的那份文档"绑定的批准码，**文档一改，码就失效**。
- **失败教训**：9 次定时任务因同一个登录问题全挂，**一周内唯一的信号是周五报告没来**。另一次 agent 把一个工具说成"含 25 份免费文档"，实际是 3 份。

**能抄**：角色分 profile；权限阶梯；**"缺了那份报告"必须是一条告警**（我们的 agent-daily-brief 曾卡 7943 秒，同一课）。

## 3. HN 用户 sksksk：把生活流水线接进来（2026-10-21）

本地跑 Hermes + local models + deepseek。做法不是让 agent 硬干，而是**先让 Codex 写小工具，再让 Hermes 调度**：

- Codex 写了个脚本：读邮件 → 提取收据 → 进 SQLite
- Hermes 用它算「哪些东西该补货了」（按购买周期和上次购买时间）
- 每周自动登录超市网站、订配送时段、把补货品加进购物车
- 火车晚点时自动替他申请赔偿
- 邮件里的待办抽出来进 Asana，能做的直接派给 Hermes

原话：「用得越多越好用，因为你会越来越清楚它能干什么。」

**能抄**：**Codex 写工具 + Hermes 当调度**，正是我们现在的分工；把重复生活/业务动作做成脚本，agent 只判断。

## 4. 小红书全链路 Skill（pigbiglong，GitHub）

一个 SKILL.md 覆盖七个工作流：首页分析 / 账号诊断 / 选题 / 创作发布 / 评论回复 / 知识库沉淀 / 爆款复刻。

- **不用 API，直接 CDP 操控浏览器**（和我们 SafeTrade 的做法一样）
- **Chrome 147+ 自带 Gemini 助手会干扰 CDP**，作者把对抗方案写进 skill 末尾的故障排查章节
- 长模板放 `references/topic-analysis-template.md`，SKILL.md 只留索引

**能抄**：skill 里写「环境坑 + 对抗方案」，别只写正常流程；大模板拆到 references。

## 5. 知乎：为什么同一个助手用着用着变笨

作者的做法是把「一间大办公室」拆成「多间专属办公室」：按群/主题分会话，每个群只装该群的上下文，需要时再跨群调记录。结果：**token 消耗直线下降，效率上升**。

**能抄**：长会话必然劣化；一件事一个会话，比一个会话塞所有事便宜且准。

## 我们的差距（对照上面五条）

1. 记忆：热记忆 98% 满，事实类的东西没有外置到文件库 → 该迁。
2. 角色：一个 profile 干所有事（交易/研究/运维混在一起）→ 该拆。
3. 权限：有 `approve_close.sh`，但批准的是「平仓」这个动作，没绑定「哪一笔、什么价」。
4. 定时任务：失败靠人发现，没有「报告没来」的检查。
5. Skill：正常流程写得多，环境坑写得少。
