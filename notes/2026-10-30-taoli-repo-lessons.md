# taoli 私有研究库：可执行结论蒸馏（2026-10-30）

来源：`github.com/w1ndtender/taoli`（只读 deploy key `hermes-tokyo`，clone 于 `/home/ubuntu/repos/taoli`，26 篇 md）。
该库是「研究证据」库，不是策略库：所有作者自述收益都标为待核验，不提供参数。以下只抽取对 PRL 期现【执行与记账】有直接约束的部分。

## 一、证据分层（最重要的一条）

报价 / 可成交 / 成交 / 已实现净收益 是四层，不能互相替代：

- 展示价差只回答价格关系；指定数量、可执行深度、时间、费用、资金费、退出约束齐全后才能谈净空间。
- 快照成本 ≠ 成交回执成本；零手续费只消除一种费用，不消除滑点、对冲、库存、延迟风险。
- 官方 API 边界：HL `allMids` 在空盘口会返回最后成交价；`userFills.fee` 已含 builderFee，记账不得再扣一次。
- 深度不足时记「无法估算该数量」，不能用局部深度或插值伪装成可成交报价。

## 二、两腿残差属于账户

- 分别记录实际买入/卖出/成交均价/手续费/资金费/剩余库存；面板盈亏、现金变化、净资产变化要能对账。
- 未成交、部分成交、最终成交分开计数；尾仓不能因为小就丢。
- 一个退出指令、屏幕到达目标价差、单边已平，都不能证明另一腿已退出。
- 仓位消失不直接说明 ADL；先查权威持仓、成交、强平/ADL 事件、余额与负债变化。
- 裸多 / 裸空 / 价差回归 / 价差扩张分别记账；账户余额上涨不能单独归因于套利。

## 三、条件版本与在途订单

- 在请求或订单等待期间改方向、改阈值，回执必须仍绑定「发出时的条件版本」；新配置不能重新解释旧动作。
- 刷新、停止循环、超时，都不能证明已提交订单不存在。
- 参照 zuudot 执行器（固定版本 README/CHANGELOG）：回执保存在内存、重连可重放、进程重启后清空 —— 客户端回执丢失 ≠ 交易所订单消失。

## 四、成本口径

- 用成交均价时，滑点已进入成交现金流，不再重复扣一次（反面：也不能漏掉 DEX swap 这类没进成交价的费用）。
- 成本比较必须同资产篮子、同名义金额、同方向、同订单类型、同费率、同统计量；均值/中位数/加权不可互换。
- taoli 工具计费按 UTC 自然月累进 3/2/1 bps，只覆盖工具费，不覆盖交易所费。

## 五、资金费机制

- 两家都有内外两层限幅：内层 ±0.05% 修正「利率−溢价」，外层再对最终费率 cap/floor；内层不是最终上限。
- Binance 2025-09-18 08:01 UTC 起改 `(N/8)×G(P,I_8)`；Bybit 仍 `G(P,I_N)`。公式版本必须绑事件时间，不能回填。
- 结算周期会因触顶自动缩短（Binance 8/4→1h；Bybit 2025-10-30 起同理），实际间隔要用结算历史确认。
- 个案：Bybit ORDER 资金费从 -2.5%（8h）跳到每小时 -0.92% —— 单期异常不能平推，也不能用瞬时值外推年化。

## 六、方法论（比结论更值钱）

- 每条假设写五栏：已观察到什么 / 相反解释 / 缺什么证据 / 怎么验证 / 是否已部署。
- 主动找反面：失败、退出受阻、遗漏成本、选择性展示、同币重复暴露。
- 不把作者自述（5.9%、3%、200ms、0.15%、30% 年化）升级为参数；软件作者说修好、单次成功、服务在线，各只是对应层面的证据。
- 收益必须有资本与时间分母；币种分散 ≠ 风险独立（可能同交易所/同抵押/同链）。
- 频繁小赚不能证明尾部安全。

## 七、落到我们这套 PRL 系统的动作

1. 新增 `reconcile_check.py`：永续现金流（已实现 + 手续费 + 资金费）与账本「价差收益」分开算，出残差；`reconcile-check.timer` 每天 09:00 跑。
2. 首次对账结果：24h 永续现金流 **−14.71**（已实现 −15.63 / 手续费 −0.26 / 资金费 +1.18），账本记 **+7.33**，残差 **−22.05** → 账本口径系统性高估，不能当已实现收益报。
3. 单腿自动对齐（`rebalance_close` / `rebalance_short`）已上线，正是「两腿残差属于账户」这条的落地。
4. 待做：账本平仓行改为记现金流金额（而不是价差推算），并把「部分成交」单独计数。
