## 1. Gang V3 fair mint：闸门是 `enabled` 字段，不是 HTTP 码

**实测（本机，2026-10-27）**

| 时间 | `/api/fair/config` | 含义 |
|---|---|---|
| 17:54 | HTTP 404 `{"error":"fair mint not configured"}` | 后端连这个接口都没部署 |
| 22:05 | HTTP **200** `{"enabled":false}` | 接口已部署，开关关着 |

→ **同一天内语义变了**。任何「用 HTTP 200/404 判开盘」的写法都会误判，正确判据是 JSON 里的 `enabled`。

**等待期的成本是 0，不用提前动钱**

- 狙击器 live 模式 17:54:49 → 22:05:53，共 **15,064 秒**
- `gate_closed` 事件 **2,236 次**（≈ 8.9 次/分，即 `poll_gate_s=5` 实测约 6.7 秒一轮）
- 真实 `sale` 事件 **0 个**；日志里 4 条 `sale` 全部是 21:15:06 的 `--fixture` 自测（假地址 `0x1111…`/`0x2222…`，`auto:false`），**不能当作成交**

**fixture 自测核出的成本模型**（与我给用户的口径一致）

- 每份 **0.001515 BNB** = 0.0015 打新价 + 1.0% 打新费；募集 15 BNB / 10,000 份
- 预算闸：单份 ≤ `max_cost_quote=0.0016`，总 ≤ `max_total_spend=0.005`，最多 3 个仓位

**代码审查发现的缺陷（未改，留档）**

`sniper.py:452-456` 用三态判定：`enabled` 为真/假/异常(None)。异常时 `live=None`，落到 `else` 分支 → 被当成「已开盘」，且按 `poll_sale_s=1.5` 秒空转。网络抖动一次就可能误报「打新已上线」并进入 1.5 秒死循环。修法：`None` 单独当作「等待」处理。

## 3. 本机 Telegram 不通：DNS 拿到被墙 IP，不是 token 问题

**现象**：`getMe` → `TimeoutError`；`getent hosts api.telegram.org` 返回 IPv6 `2001:67c:4e8:f004::9`。

**修法**：`/etc/hosts` 钉 `149.154.167.220 api.telegram.org` + 请求走 `curl -4`。

**验证**：钉之前超时；钉之后 `sendMessage` 返回 `sent: True msg_id 4`，`pairing approve telegram 5086267048` 通过，网关 `✓ telegram connected`。

**副作用教训**：钉 hosts 是长期负债——Telegram 换 IP 时 bot 会静默失联，排查顺序第一条就是看这一行。安全侧的连带改动：VPS 上 SSH 密码登录已关（实测 `Permission denied (publickey)`），聊天里出现过的密码同时失效。
