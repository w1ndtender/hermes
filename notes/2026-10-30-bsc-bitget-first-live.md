## 真正的发现：链上单边换手 1.8%，不是 0.25%

```
BAW 报价实测：买 0.0143 BNB → 453.667 SIREN，池中价 0.02167，成交 0.022064（贵 1.82%）
卖 451.4 SIREN → 0.014026 BNB，折 0.02174（比中价低 0.3%）
往返 ≈ 2.2%（不含 Bitget 0.06%）—— 原来的成本模型写 0.5pp，错 4 倍
```

推论：**SIREN 的 2.5% 基差在链上执行后是负期望**。要么把换手成本压到 0.4% 以下（自建
Pancake Infinity / Uniswap v4 路由 calldata，指定 hook 和费率），要么换低成本现货腿
（同所现货 API 0.1%，划转免费）。

## 踩过的坑（都已修）

- Bitget `40774`：单向持仓模式带 `tradeSide` 被拒 → 不带；平仓用反向市价 + `reduceOnly=YES`
- Bitget `40773`：`tradeSide=close` 只能在双向持仓用
- BAW 在 systemd 下找不到 → 必须写绝对路径 `/home/ubuntu/.npm-global/bin/baw`
- `bget("BNBUSDT")` 会把后缀拼成 `BNBUSDTUSDT` → 返回 0，导致算出 −100pp 假止损；用 `bget("BNB")`
- 卖出全部余额报 `balance insufficient` → 卖 99.5%，留 0.5% 余量
- 用 DexScreener 中价算盈亏会低估成本 → 只用 BAW `market-order quote` 的真实卖出价

## 下次的前提条件

2. 基差 ≥ 1.5%（覆盖 0.5% 成本 + 0.5pp 利润 + 0.3pp 缓冲）才进场
3. 单笔仍然 ≤ $10，连做 3 笔都是正收益再放大
