# 期现价差实战手册（跨标的可复用）

> 来源：2026-10-26 ~ 10-30 PEARL（SafeTrade 现货 ↔ HL `io:PRL` 永续）真实下单、真实亏损、真实现金对账。
> 每条都带数字，都是在账户里付过钱的。换标的（BSC 链上现货、别家 CEX 现货）照样适用。

## 0. 一句话

**进场看「收窄空间 − 手续费 − 盘口宽度」够不够，平仓只看现金流。价差 pp 只描述两条腿的相对变化，不代表钱变多。**

## 1. 成本结构（必须先算，算错就白干）

```
手续费：现货 0.1%×2 + 永续 0.009%×2 = 0.218%
盘口宽度：现货买卖价差实测 1.20% ~ 3.10%（不是 0.57% 那种理想值）
一轮盈亏 ≈ 价差收窄幅度 − 0.218 − 两边盘口宽度
```

实盘例子：收窄 1.19pp − 0.22 − 1.29 = **−0.32pp**，看着"赚了 1.19pp"，其实是白干。
推论：**价差 2.0% 进场，至少要收窄 2.1pp 才有钱**（盘口 1.4 + 费 0.22 + 利润 0.5）。

## 2. 三个把结论带偏的陷阱（都踩过）

### 陷阱 A：把「价差收窄」当收益
按 3.61% → 0.5% 推算 +$16，实际现金流 **−0.5**。
价差是报价层，钱是现金流层；中间隔着盘口宽度和部分成交。

### 陷阱 B：信任自己 state 里记的入场价差
state 写 3.61%，交易所持仓均价反推只有 **0.21%**（中间被 reconcile 重建过）。
等于"在价差几乎为 0 的位置建仓"，怎么等都等不出利润。
**规则：每轮用交易所真实持仓均价校准，并从它反推现货成本，不信本地缓存。**

### 陷阱 C：只报赚的那条腿
空头腿 +0.27U 就报"赚了"，现货腿 −1.00U 归到"历史成本另算"。
**规则：只报两腿合计现金流，单腿浮盈一律不算。**

## 3. 单腿（裸空/裸多）是最大的操作风险

事故：平仓时现货成交 200 颗，永续只平到 140 颗 → 攒出 **70 颗裸空**，最后在 1.6888 买回（建仓 1.6026），**一次确认亏损 −$6**。

规则：
- 每 5 秒对账 `|永续|` vs `现货`，偏差 > 1 颗就动**永续**补齐（用户口径：一般动永续）
- 平仓时先卖现货、再买回等量永续；现货卖光后剩余永续必须单腿买回
- 一个退出指令、单边已平、屏幕到达目标价差 —— 都不证明另一腿退出

## 4. 进场：倒金字塔（价差越大进越多）

```
≥2.0% → 40 颗 ｜ ≥2.5% → 80 ｜ ≥3.5% → 120 ｜ ≥4.5% → 160   （上限 400）
先空永续 → 立刻买等量现货 → 买不够立刻砍永续，绝不留单腿
单笔 ≤ 盘口 1% 内深度 15%（砸盘口 = 自己把价差买没）
资金费 <0.003%/h 时门槛 +0.5pp（收不到租金就要更大价差）
现货盘口宽 >1.0% 不开仓（平仓差价会天然很负）
```

## 5. 平仓：正金字塔（价差越窄平越多）+ 现金闸

```
全平线锚定历史 P5（PEARL: 0.87%），沿「入场 → P5」分 1/3、2/3、3/3
累计平仓 1/6 → 3/6 → 6/6
每刀 ≈10 USDT（≈6 颗），深度不足单量 3 倍就跳过这一刀
价差反弹回上一档之上 → 整档停手
```

**现金闸（唯一放行条件）**
```
每颗现金 = (现货卖买一 − 建仓买价) + (永续建仓卖价 − 买回卖一)
再扣 0.218% 手续费，仍为正才允许这一刀
```

## 6. 档位必须锚定历史低位，不能"入场 − 固定 pp"

PEARL 分布（1,271 分钟点）：最低 −1.09 ｜ P1 +0.21 ｜ P5 +0.87 ｜ P10 +1.30 ｜ 中位 +2.62 ｜ 最高 +7.22

| 入场 | 「−3.7pp 全平」线 | 历史达到时间占比 |
|---|---|---|
| 2.0% | −1.7% | **0.0%** |
| 2.5% | −1.2% | **0.0%** |
| 3.5% | −0.2% | 0.8% |
| 4.5% | +0.8% | 4.1% |

结论：入场越低，档位必须越浅，否则第三档永远触发不了。用 P5 当锚，档位随入场缩放。

## 7. 对账（每天必跑）

```
永续现金流 = 已实现 + 手续费 + 资金费   ← HL userFills / userFunding
现货现金流 = 卖出收入 − 买入成本        ← SafeTrade /trade/market/trades
残差 = 现金流 − 账本；|残差| > $3 先查单腿，再谈收益
```

首次对账结果：永续 −14.71、账本 +7.33、残差 **−22.05** → 账本口径系统性高估。

## 8. 上线顺序（跳步就是交学费）

1. 纸面跑通一整轮（含平仓与对账）
2. 20 颗真仓跑通一轮（真成交、真手续费、真单腿风险）
3. 才按金字塔放大

今天违反过这条（直接从 299 颗起），代价是 70 颗裸空 + 一轮白干。

## 10. 单腿会在「不报错」的情况下发生（2026-10-31 群聊 46.5 万条里最贵的一课）

1. **撤单 ≠ 撤单成功** — 撤单请求发出去也可能留活单；此时挂新单会两边都成交 → **撤后回读订单状态=已撤，再挂下一档**。
2. **黄色 warning 不是 error** — 「transaction replaced」只是提示，程序不抛异常 → 只看 error 会漏单腿，必须比对持仓。
3. **单腿后 pnl 可能一条记录都没有** — 有人的合约被平、现货还在，盈亏里什么都没有 → **只信两家交易所的持仓，不信 pnl**。
4. **两腿数量不匹配是静默的** — 实例：链上成交 1 笔、CEX 成交 6 笔，没报错，成交信息里也看不到 → 数量对账必须每轮做。
5. **补腿失败就反向平掉已有腿** — 补不上还硬补 = 裸仓扩大；兜底动作是先平掉已成交那条腿。
6. **每次单腿留原始回执** — 出问题要能证明「几点几分哪条腿成交多少」，否则无法归因。
7. **残仓不足一个 size → 两边同平，并记 idx** — 群里原话：拿 idx 当去抖，下一个带 size 的 idx 进来才允许再平，避免同一笔残仓被反复补/平。
8. **粉尘清零** — 永续已 0、现货还剩 0.2 颗以上，直接市价卖掉（我们 0.46 颗挂了很久，账面永远差一点）。

## 11. 价差判定还缺三个约束

9. **确认窗口** — 别在价差刚出现就冲：「开始见了价差就冲，后面发现亏的很，就加入确认窗口，确认价差真实存在以后再冲」→ 连续 3 次达门槛才挂。
10. **数据有时效** — 单边报价 >5 秒、永续 >3 秒即视为过期（2026-10-31 收紧，见 §23.1；taoli 工具的标准是任一边 >3 秒不下单）（DEX 要等两次询价结束才计时，CEX 按交易所服务器时间）→ 判定取两边时间戳的最小新鲜度。
11. **触发价差 ≠ 成交价差** — 「价差 1.3% 触发，但两笔成交后价差没有任何保证」→ 成交后立刻用回执价重算真实基差，并写进 state。
12. **口径固定 `2/(a+b)`** — 分母用两价之和，不用单侧除法（差 0.3~0.5%），也别拿标记价冒充盘口价。

## 12. 爆仓与 ADL 的真实规则（此前手册完全没有）

13. **ADL 触发条件已改** — 多数交易所不是「保险基金归零」才触发，而是「基金余额从高点回落 x%」→ 触发频率越来越高。
14. **ADL 排序对「浮亏 + 低杠杆」不友好** — ORCA 事件亲历者：浮亏状态下杠杆越低，减仓排名越靠前 → **HL 空单不要为了「安全」压到 1x，保持 3x 左右 + 保证金冗余**。
15. **强平顺序是先吃订单簿、再切 ADL** — HL 的 hyperp 用逐仓隔离，盈亏与其他资产隔离，坏账不扩散（XPL 事件官方描述）。
16. **强平按破产价成交，差额进保险基金** — 实际损失比按现价估算的大。
17. **强平时没有「先卖后买」的选择权** — 有人的合约被强平成交、现货没成交，现货随后暴跌 → 我们「绝不先买回永续」只在主动平仓时成立，被动强平只能靠保证金冗余。
18. **指数成分会被挑着打** — Gate LA 2025-06-04：kucoin 被塞进指数，2000 刀拉盘 → 40+ 人爆仓、人均 3 万刀，平台回复「未发现异常」，维权花 6000U → **定期查 `io:PRL` 的 oracle 成分权重，含单所高权重时降档或停做**。
19. **薄盘口本身是操纵目标** — 我们 1% 内只有 300–334 颗，单笔 20 颗已占 6% → 单笔 ≤ 深度 15%，价差大但无量时不追。
20. **平台拒赔是常态** — 别把「平台会赔」写进收益模型。

## 13. 资金费规则会在持仓中被改

21. **周期和上下限会变** — 实例：币安把 SKHYNIX/SAMSUNG/HYUNDAI 从 8h 改 4h、上下限压到 ±0.50%；ARIAUSDT 也从 8h 改 4h。
22. **触及上下限会联动缩短周期** — 上周期打到上下限，结算频率可能 8h/4h → 1h，且 15 分钟内生效 → 门槛判断要读实时周期与 cap。
23. **资金费是预测值** — 账单以结算事件为准（我们已用 HL `userFunding` 对账，继续保持）。
24. **别把 CEX 的「避开结算中间半小时」搬到 HL** — HL 每小时结算，照搬会把一半时间关死。

## 14. 记账四件套（补 §7 只剩「残差」的缺口）

25. **四段名义 ≠ 本金** — 开仓两段 + 平仓两段，收益率分母只能用真实投入。
26. **残仓与门槛以下的仓位仍占保证金、仍付资金费** — 不能按 0 处理。
27. **手续费、资金费、滑点分项记** — 合并成「成本」以后无法归因（10-30 残差 −22 就是这么来的）。
28. **标记价 / 指数 / 成交价分开建账；收益率注明分母** — 「153.3 bps」可能是按成交额，不是本金回报率。
29. **现金变动与持仓变动分开记** — 出入金不算盈亏。

## 15. 运维与外部状态

30. **交易所调仓/改系数时要停循环** — 实例：BN 调整期间自动循环必须关掉，调整后仓位 ×1.10、pair 系数 1.05476 → 0.95719；**沿用旧系数会把正常调整误判成巨大价差**。
31. **数据源单点故障会打穿策略** — HL 曾出现报价频率变低、Bitget 指数不显示 → 加数据源健康检查（连续 N 次取不到就停手并推送）。
32. **`systemd is-active` 不是健康检查** — 用日志断言（本轮门槛/持仓/余额三行必须出现）。
33. **启动时打印实际生效参数** — 配置错误比策略错误更常见（群里「minA 应该填负数，我填错了，−10 反向，还被扣资费」）。
34. **同名 ticker 不同标的不能合并** — Aster 的 `PRL` $0.094 ≠ 我们的 `PEARL` $1.80。
35. **策略有寿命** — 2021–2023 随便撸，现在卷死；理论月化 25–40% 不是稳态，别拿它做计划。
36. **不要为补保证金临时调钱** — 群里有人借 6k 补仓最后亏 19k；我们的边界是日亏 $20 停手。

## 18. 2026-10-31 复盘：取价市场与下单市场错位（179 次挂单 0 成交的根因）

- 事实：`lib.spot_snapshot()` 写死 `pearlusdc` 取价，`config.spot_market=pearlusdt` 下单。
- 两个市场的盘口完全不同：**usdc 1.41 / 1.45（宽 2.8%，1% 内深度 277 颗）**，**usdt 1.43 / 1.44（宽 0.7%，深度 8,593 颗）**。
- 后果：① 价差虚高 1–4pp（用 1.45 对永续 1.446 算出 5.4%，真实 1.44 对 1.446 只有 1.2%）；② maker 挂单价按 usdc 买一 1.41+1tick = 1.42，在 usdt 市场里低于真实买一 1.43，**永远排不上**；当日 179 次 `open_abort_spot_first want=20 got=0`，另有 2 次 `open_fail 名义 $9.4 < $10`（早期 slice=$10 太小）。
- 已修：`spot_snapshot(market)` 参数化 + `book()` 读 `config.spot_market`；采集/提醒/看板同步。修后日志变为「现货卖一 1.4400（1%内 8593 颗）」，真实挂单口径 1.20%。
- 口径切换：**2026-10-31 22:12 之前的 ticks 全部是 usdc 口径，不能与之后的数据混算**。
- 方法论：挂单长期 0 成交但市场有成交 → 先查「取价市场 vs 下单市场」，再查排队与价格。

## 19. 语料第二轮蒸馏：三条与「执行速度」直接相关的规则

> 来源：taoli 群 46.5 万条里带「分批/吃满/排队/盘口」语义的长消息（已剔除新闻与喊单）。只保留能改代码或改参数的。

### 19.1 机会窗口比精细更重要：价差没吃满 = 没赚到

- 群友复盘原话：「本来都知道要回锚，但是**没吃满，价差没吃满，仓位也没吃满**」；另一条「**优先级没搞清楚**」——两次都把「看清了但没建够仓」列为主要亏损原因。
- 对照我们自己的数据：pearlusdt 挂单中位 **7 秒**成交、价差 ≥1.0% 的窗口 1.5 小时出现 15 次、每次持续 **2–6 分钟**。
- 结论：单笔 **20 颗 + 等待 45 秒** 的组合，一次窗口只能吃 40–80 颗，**吃不满**。应改成单笔按深度 5% 计算（当前 1% 内 2,897–18,538 颗 → 单笔 100–150 颗），等待 25 秒（P90 22 秒）。
- 这条**要用户点头**（改的是仓位节奏，不是 bug 修复）。

### 19.2 1 tick 宽 + 两侧大挂量 = 做市机器人在守，别挂单排队

- 群友原话：「一个币手续费很高的时候，会有 LP 机器人进来。这个 LP 机器人通常会以**很窄的区间**干活，**1 tick–3 tick**。涨出区间了他就在当前位置的下一个 tick 补，跌了就在上一个 tick 卖」。
- 含义：这种时段我们挂买一，前面排着几千颗机器人挂单，**永远轮不到**；而价差看起来依然存在，会误判成「挂了不成交」的 bug（本手册 §18 的错位 bug 就是这么被掩盖的）。
- 已落地：`book()` 增加 `bid1_size/ask1_size/lp_bot`，判定 `宽度 ≤1 tick 且两侧各 ≥500 颗`；命中且走 maker 通道时本轮跳过并推送一次日志（`skip_lp_bot`）。吃单通道不受影响。

### 19.3 建仓价差 ≠ 平仓价差，两腿是两个独立的订单簿

- 群友原话：「\*\*这两个数字一般来说不是一定会相等，因为分别是两个 market 的订单簿\*\*」。
- 含义：进场用「永续买一 − 现货卖一」，平仓必须用「现货买一 − 永续卖一」重算，不要把进场价差当对称收益。手册 §13 已强调「触发价差 ≠ 成交价差」，这条更进一步：**两个方向的口径本身就不同**。
- 已落地：`close_edge_of()` 单独计算，收益预估禁止复用 `edge_of()` 的数。

## 20. 第三轮蒸馏：成本、成交权、指数污染

> 来源：taoli 群长消息（已剔除新闻/公告），加上我们自己从交易所接口实测的费率字段。

### 20.1 成本结构（实测，不是估计）

- SafeTrade 订单字段 `maker_fee = 0.001` → **0.1%/边**，往返 **0.2pp**。
- HL `io:PRL`（userFees 实测）：maker **0.015%/边**、taker **0.045%/边**。
- 一进一出：现货 0.2 + 永续 0.03（maker）= **0.23pp**；永续走吃单 **0.29pp**。
- 结论：**成本的大头在现货，不在永续**。毛价差 1.0% 净剩 0.77pp；毛 1.5% 净剩 1.27pp。
- 已落地：`exec.py` 里 `SPOT_FEE_ONE_WAY / PERP_MAKER_FEE / PERP_TAKER_FEE` 三个常量，日志每轮打印「净 +x.xx pp（成本 0.23）」。

### 20.2 记账必须用成交均价 `avg_price`

- SafeTrade 订单返回里有 `avg_price`（实测 `price=1.44 / avg_price=1.435` 会出现）。
- 按挂单价记账会把收益算错，残差越滚越大（历史上出现过「pp 当钱记」的同类错误）。
- 已落地：`spot_order()` 的 cost 累加改用 `avg_price`，缺失才回退挂单价。

### 20.3 吃单会被「价格区间执行规则」剪掉（Binance PRER，2026-04-14 起）

- 吃单进入执行阶段时，交易所按当时参考价算一个动态允许区间；**超出区间的部分立即过期**，状态 `EXPIRED`、原因 `EXECUTION_RULE_PRICE_RANGE_EXCEEDED`；**允许部分成交**。
- 含义：薄盘口 + 快速波动时，"吃单成功"这个假设是错的。必须处理「部分成交 + 剩余过期」，而不是当成全成或全败。
- 落地要求：吃单后回读 `filled_amount / avg_price`，剩余量按新盘口重算；不可用「下单量」当「持仓量」。

### 20.4 挂单不成交 ≠ 价格不对：还有「成交权」

- CEX 正在给做市商推出只与散户成交的专属挂单类型（RPI 类；Binance / Bybit / OKX 都在推，HL 有类似保护），做市商被"保护"后，普通挂单的排队与成交权被削弱。
- 群内原话：这类机制让「新闻交易/延迟套利」的利润下降 30–50%。
- 对我们的意义：价差在、价格也对，照样可能吃不到。判断「系统坏了」之前先排除三件事：① 取价市场错位（§18）② LP 机器人 1-tick 守卫（§19.2）③ 成交权/排队。

### 20.5 指数被「停充停提的交易所」污染 → 价差不可搬平

- 案例（群内）：ESPORTS 链上与币安永续出现最高 **45%** 价差；根因是 Gate / MXC / Bitget **暂停充值**，但仍被计入币安合约的价格指数（Gate 10.52% / MXC 15.78% / Bitget 15.78% / PancakeV3 52%…）。
- 含义：这类价差是「算出来的」，不是「搬得动的」。看到离谱价差（>5%）第一反应应该是查指数成分有没有停充/停提/低流动性权重，而不是找资金。
- 落地要求：进场前若 `|mark − perp_mid| > 0.5%` 或价差 > 5%，先查指数成分状态，不查清不做。

### 20.6 滑点估算（群内方法，可直接用）

- 原话：「交易 100u 看价格变化多少，然后直接用总的差价除以这个价格变化再乘以交易额」。
- 用法：用 5–10 颗小额单实测「单量 → 价格位移」，把系数写进 `entry_depth_ratio`；比拍 15% 更准。

## 21. 第四轮蒸馏：用分位数定门槛、平台会替你做决定、永续腿的真实参数

### 21.1 门槛按「近期分位数」定，不按拍脑袋的固定数

- 群内 CL/Brent 案例的做法：「等 >95th 分位或 <-5th 分位才进」，不是"设个 2% 就去等"。
- 我们实测印证：近 6 小时可执行价差 **P80 = 1.06%**，而当时挂的门槛是 **3.00%** → 系统等于关死。
- 已落地：`pct_floor()` 读取 ticks 里真实口径的 `exec_spread`，每 30 分钟打印 P80 建议；`config.pct_th_mode=true` 时直接把它当门槛（默认 false，先只观察）。
- 纪律：门槛必须 **≥ P80**，否则一半以上时间在低于自身分位的位置进场，赚的是尾部的钱、亏的是均值。

### 21.2 平台会替你做决定：成交价偏离必须留痕

- 群内实例：吃 17% 与 −11% 价差时，**Gate 直接把空单按 20% 拔高平掉**，仓位凭空消失，用户以为误触了一键平仓。
- 结论：交易所风控/清算可以以远差于盘口的价格结束你的仓位，且不报错。
- 已落地：`spot_order()` 结束后比对「挂单价 vs 实际成交均价」，偏离 >0.3% 就写 `fill_price_deviation` 事件并推送 Telegram（建仓和平仓都覆盖）。

### 21.3 `io:PRL` 永续腿的真实参数（`metaAndAssetCtxs` 实测）

| 项 | 值 |
|---|---|
| 未平仓量 OI | **470 万颗** |
| 24h 成交额 | **$135 万** |
| 最大杠杆 | **3x**，**仅逐仓**（`onlyIsolated`） |
| 标记价 / 指数价 | 1.4672 / 1.4628（溢价 0.2%） |
| 资金费 | **+0.0219%/h ≈ 0.53%/天** |

- 我们 300–500 颗只占 OI 的 **0.01%**，对价格没有影响力，别担心"自己砸自己"。
- 资金费是这条策略里**唯一可预期**的现金流：300 颗（≈$438）≈ **$2.3/天**；价差是波动的、资金费是天天有的。
- 仅逐仓意味着：仓位保证金独立，现货腿的浮盈不能给永续腿兜底 → 永续账户必须留够钱（满仓 519 颗 2x ≈ $371 保证金 vs 账户 392 USDC，只剩 $21 缓冲，**太薄**）。

### 21.4 指数来源必须查清：价差可能永远搬不平

- 群内有专门的「指数成分变更」监控机器人（订阅 Binance/OKX/Bybit/Bitget 的成分与权重变化），说明成分是被套利者当风险项管理的。
- 我们要回答的问题：`io:PRL` 的指数是否包含 SafeTrade？如果不含，HL 的定价与 SafeTrade 现货之间就没有直接搬平通道，价差只能靠"其他能搬的人"消化 —— 那么收敛速度与幅度都要打折。
- 动作：进场前把指数来源确认一次，写进本节；没确认前，把价差当作"可能不收敛"处理（止损 2pp 就是这个原因）。

## 22. 第五轮蒸馏：笔数本身是成本、费用比较必须归一到同一结算周期

> 这一批 110 条长消息里，超过一半是 Trendbot 的费率广播和上币公告（噪声），真正可用的只有两条。

### 22.1 高频小单会把利润磨光（有量化案例）

- 群友的批量结算报告：**501 笔**循环、单边成交 **122,887 U**，预估收益 **2,003 U**；拆开看是
  - 某个代币 **495 笔 → 合计 −3.4 U**（几乎白做，还倒亏）
  - 另一个代币 **6 笔 → 3,024 U**
- 结论：**笔数本身就是一笔成本**（排队损失、滑点、固定手续费、每次下单的延迟），小单循环能把毛利吃干净。
- 已落地：`rounds_today()` 统计当日 `open` 事件，`config.max_rounds_per_day=12`（默认 12 轮/天），到上限即停止开新仓并打印原因。
- 对我们参数的含义：单笔 20 颗 × 每天几十轮是**最差的组合**；应该「单笔大 + 轮次少」。

### 22.2 比较资金费前必须归一到同一结算周期

- 群里提醒的形式是「4 小时基准」：Bitget 原始 −1.80%（4h）、Bybit 原始 −2.00%（**2h**）→ 归一到 4h 后分别 −1.80% 和 **−4.00%**，差距从 0.2% 变成 2.2%，**方向都可能反过来**。
- 我们这边 HL 是 **1 小时**结算、CEX 多为 4h/8h，所以：
  - 日志里一律标 `%/h`（现在已经是），不要出现裸 `%`；
  - 跟任何外部数字对比前，先乘以/除以结算周期；
  - 年化换算用「每小时 × 24 × 365」，不要用「每 8 小时 × 3」。

### 22.3 指数成分要连「充提状态」一起看（补 §21.4）

- 群里的成分通知机器人不只报权重，还报每条链的充提状态，例如 HEMI：Binance 权重 74%，但 BEP20 **充❌**、Hemi 链 **充❌ 提❌**。
- 权重高但充值关闭 = 价格由「搬不动的钱」定，价差不可套。这条和 §20.5 的 ESPORTS 是同一个坑的两种表现。
- 动作：确认 `io:PRL` 指数成分时，必须同时看成分里每个来源的**充值/提现是否开启**。

## 23. 第六轮蒸馏：3 秒时效标准、延迟实测、返佣砍成本

### 23.1 报价时效标准是 3 秒，不是 15 秒

- taoli 工具的原话（更新日志）：「修改价格过期逻辑：**超过 3 秒显示黄色，超过 9 秒显示红色。A 或 B 任意一边超过 3 秒就不再下单**」。
- 我们实测的取数延迟（腾讯云东京 → 交易所）：
  - HL `l2Book`：**20–30 毫秒**
  - SafeTrade `depth`：**0.43–0.77 秒**（每次），exec 一轮要取 tickers+depth ≈ 1–1.5 秒
- 结论：瓶颈在 **SafeTrade**，不在机房；但它仍是亚秒级，没有理由容忍 15 秒的报价。
- 已落地：`max_spot_age_s=5`（原来是 15）、`max_perp_age_s=3`（原来是 5）。

### 23.2 延迟优势是真的，但要看清优势在哪条腿

- 群友在问「腾讯云日本延迟多少，AWS 30ms 但服务器性能差」——我们就在东京腾讯云，HL 实测 **20–30ms**，属于最优一档。
- 但套利的两条腿延迟差一个数量级（20ms vs 500ms），意味着**现货腿才是决定成交的那条腿**，优化方向应放在 SafeTrade 侧（减少取数次数、复用挂单），而不是继续压低 HL 延迟。

### 23.3 返佣能把一进一出成本砍掉近一半（待谈）

- 群内实例：Bitget 直接开代理 **50% 现货 / 60% 合约返佣**（不用换号）；Bybit 有 18% 一类的常规返佣链接。
- 我们的成本结构：现货 0.1%/边是大头 → 拿到 50% 返佣后 **0.05%/边**，一进一出从 **0.23pp 降到 0.13pp**。
- 对 1% 毛价差的意义：净利 0.77pp → **0.87pp（+13%）**。这是**不改策略就能拿到的收益**，优先级高于调参。
- 待办（需要用户出面）：问 SafeTrade 有没有 API/代理返佣；没有的话，这部分成本只能认。

### 23.4 交易所面板的 PnL 有统计延迟，只信自己的账本

- 群友：「还以为他们统计有延迟……我直接 app 上下几单立马显示了那两单，今天工具套的一单都不算」。
- 纪律：当日盈亏、轮次、资金费一律用本地 `exec_ledger.jsonl` + `spread.db` 计算，不读交易所面板（我们已经是这样，写进手册防止以后偷懒）。

### 23.5 两种「静默失败」的补充

- 「Bitget 市价单可能会**不成交也不报错**」——已经踩过的同类坑（§10）。
- 「DEX 统一改为：重试 5 次，每次滑点增加 0.1%，即 0.1%～0.5%」——**重试必须递增滑点**，固定重试只是重复失败。
- 「余额不足时应灰色提示不下单，不要红色报错打断 loop」——loop 韧性：余额不足属正常状态，不是异常。
