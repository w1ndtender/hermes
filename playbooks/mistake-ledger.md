# 错误台账（每条都必须有「防复发的代码或检查」）

规则：只记**已经造成实盘损失或静默失效**的错误。每条三问：症状是什么、根因是什么、哪一行代码/哪条检查保证它不再发生。
没落到代码或自检里的，一律算「还没修完」。

## 1. 取价市场 ≠ 下单市场（2026-10-31，最贵的一次）

- **症状**：一天 179 次 `open_abort_spot_first want=20 got=0`，挂单从不成交，但市场每分钟都有成百上千颗成交；同时价差读数虚高 1–4pp（当天算出 18 段 ≥3%，最高 5.43%）。
- **根因**：`lib.spot_snapshot()` 写死 `pearlusdc` 取价（1.41/1.45，深度 277 颗），`config.spot_market=pearlusdt` 下单（1.43/1.44，深度 8,593 颗）。maker 挂单价 = usdc 买一 1.41 + 1 tick = 1.42，在 usdt 市场里**低于真实买一**，永远排不上队。
- **防复发（已落地）**：① `spot_snapshot(market)` 参数化，`book()` 读 `CFG_SPOT_MARKET`；② `main()` 启动自检 `CFG_SPOT_MARKET == config.spot_market`，不等就推送并停手；③ `drift_check.py` 扫描所有脚本里写死的 `pearlusd[ct]`，与 config 不一致直接拒绝重启；④ `tests_exec.py` 3 条断言（常量一致 / 允许传 market / 默认值一致）。
- **配套**：口径切换时间写进手册（22:12 之前的 ticks 是 usdc 口径，作废）。

## 2. 单笔名义低于交易所下限（2026-10-31）

- **症状**：`open_fail leg=perp err=名义 $9.4 低于交易所下限 $10`，现货已买 6 颗后又回滚（`open_rollback_spot qty=6`），白付一次来回。
- **根因**：颗数下限写死 `max(6.0, ...)`。6 颗 × $1.44 = $8.64，低于 HL 最小名义 $10。
- **防复发（已落地）**：`_min_qty = max(2, 10.5 / spot_ask)`，所有切片都夹在 `[_min_qty, ...]` 之间；改价后用 `tests_exec.py` 覆盖。

## 3. SafeTrade `amount` 只接受 2 位小数（2026-10-30）

- **症状**：422 `market.order.non_round_amount`；日志表现为「现货只买到 0 颗」「现货只卖出 0/20 颗」，而 systemd 一直 active。
- **根因**：传了 6 位小数；且错误被上层吞掉，看起来像「没人卖」。
- **防复发**：下单前 `round(amount, 2)`；订单返回非 200 时把 body 打进日志（不要再静默 continue）。

## 4. 撤单不回读（2026-10-30 ~ 10-31）

- **症状**：阶梯换档时旧单其实还挂着，两档同时成交 → 多出来的现货变成没有对冲腿的裸多。
- **根因**：把「撤单请求返回 ok」当成「已撤销」。
- **防复发**：`cancel_wait_orders()` 撤完重新拉 `state=wait`，最多 3 次重试；仍在途就推送「撤单回读失败」并返回 0，**本轮不挂新单**。

## 5. 日志把并列条件写成「且」（2026-10-31）

- **症状**：资金费明明 +0.0324%/h（够），日志却打「资金费 < 0.02%」，用户据此要求改错的地方。
- **根因**：`f"... < X% 且资金费 < Y%"` 无条件拼接，没分支判断。
- **防复发**：拦截日志只打印真正成立的那一条原因（`_tail` 分支），改完对着一轮真实日志念一遍再提交。

## 6. 粉尘仓长期留在账上（2026-10-29 ~ 10-31）

- **症状**：永续 0 颗、现货 0.46 颗，账本永远差一点，闸门分母失真。
- **根因**：`reconcile_spot_gap()` 里 `gap < 2` 直接 return，没处理「只剩零头」的情况。
- **防复发**：`perp < 0.01 and real_spot >= dust_min_qty(0.2)` → 市价卖掉 + 推送「🧹 清粉尘」。

## 7. state 里的入场价不可信（2026-10-30）

- **症状**：state 写入场价差 3.61%，按交易所持仓均价反推只有 0.21%，整轮「收窄 1.19pp 赚了」全是虚构。
- **根因**：`reconcile()` 重建批次时用「开仓均价 / 当前价」派生入场价差，跟着行情漂。
- **防复发**：入场价差只允许来自批次加权均价或历史值，**不许由当前行情派生**；报收益前先回读 state 与交易所均价。

## 8. 把价差 pp 当钱（2026-10-30）

- **症状**：账本记 +7.33，永续真实现金流 −14.71，残差 −22.05。
- **根因**：用「价差收窄 × 名义」推算收益，没扣两边盘口宽度和部分成交。
- **防复发**：平仓只认现金闸（实际回执价 + 2/(a+b) 口径）；对账每天跑 `reconcile_check.py`，|残差|>$3 先查单腿。

## 9. `systemd is-active` 不是健康检查（2026-10-30）

- **症状**：服务 active，但每轮抛 Traceback，止损/平仓全静默失效。
- **防复发**：部署后必须看到「开仓价差 / 平仓价差」三行日志；`deploy.sh` 顺序 pyflakes → 自测 → 重启 → 打印最新一行。

## 10. 符号拼接把 `BNBUSDT` 变成 `BNBUSDTUSDT`（2026-10-30）

- **症状**：ticker 返回 0 → PnL 算成 −100pp → 触发假止损。
- **防复发**：自写 ticker 只接受裸符号（`BNB`）；`if not last: raise`，不许把 0 当价格。

## 11. 表加列后位置参数 INSERT 静默失败（2026-10-30）

- **症状**：ticks 从 10 列扩到 12 列，采集每 60 秒报 `table ticks has 12 columns but 10 values were supplied`，看板停在 18 小时前。
- **防复发**：INSERT 一律写显式列名；看门狗加「最新数据陈旧 >5 分钟自动重启采集并报警」。

## 12. OKX v5 废弃伪装成签名错误（2026-10-31）

- **症状**：`50113 Invalid Sign`，看起来像密钥填错。
- **根因**：`/api/v5/` 已废弃且用 HMAC-SHA1；v6 要 HMAC-SHA256。
- **防复发**：签名类报错先换版本+算法验证（同一把 key 能通即为协议问题）；v5 会直接回 `50050 V5 API is being deprecated`。

## 13. 盘口宽度闸会连止损一起拦掉（高危）

- **症状（潜在）**：现货买卖价差 > `max_spot_book_spread=3%` 时 `service_close()` 直接 `return False`，**没有例外**。也就是说盘口一宽，止损、到目标价、强平前减仓全部被静默禁用。
- **根因**：宽度闸写成了无条件 return，本意只是「别在宽盘口主动止盈送钱」。
- **已修**：`service_close(..., forced=False)`，只有非强制平仓才被拦；止损/目标价/浮亏止损/保证金线走 `forced=True`。

## 14. `ticks.exec_spread` 全表为 NULL（数据静默失效）

- **症状**：2,357 行 ticks 里 `exec_spread` 全是 NULL，看板/复盘用的「可执行价差」其实是空的。
- **根因**：`collect.py` 读了 `p["perp_bid"]`，而 `perp_snapshot()` 只返回 mark/oracle/funding/oi/volume —— 键不存在被 `.get` 吞掉。
- **已修**：collect 单独拉 `l2Book` 取永续买一/卖一，并按 `2/(a+b)` 口径计算；重启后首行已写入（1.70%）。

## 15. `save_state()` 非原子写

- **症状（潜在）**：进程被杀/断电时 `write_text` 可能留下半截 JSON → 下次启动 state 解析失败 → **本地以为空仓而交易所仍有真实持仓**，止损与平仓全部失效。
- **已修**：写 `.tmp` → `os.replace` 原子替换，并保留一份 `.bak`。

## 16. 单笔止损上限 > 当日亏损上限

- **症状**：`max_loss_usd=25` > `max_daily_loss_usd=20`，一次止损就直接击穿日限、当天停手。
- **已修**：`max_loss_usd=12`（单笔止损必须小于日限，留出两次容错）。

## 17. `HARD_MAX_HOLD_HOURS=12` 是死常量（未实现超时强平）

- 定义了但没有任何地方使用。不要误以为有「持仓 12 小时强制平」。
- 用户口径是不要超时强平（会在结构没坏时平在最差价位），所以保留死常量也无害，但必须写在台账里，避免下次误判。

## 18. maker 挂单等待 45 秒会阻塞主循环（未修，待决策）

- 挂单期间不出止损、不检查保证金、不做对账；极端行情下最坏情况是「45 秒没人管仓位」。
- 处理选项：① 缩短 `spot_maker_wait_s` 到 15–20 秒；② 在 `spot_order` 的轮询里插入一次风控检查；③ 把下单放线程。默认不改（当前仓位 0，风险敞口有限），等用户拍板。

## 19. 记账用挂单价而不是成交均价

- **症状（潜在）**：`spot_order()` 用 `filled × 挂单价` 累加成本，而 SafeTrade 返回里 `price` 与 `avg_price` 会不同（实测 1.44 / 1.435）。
- **已修**：优先用 `avg_price`，缺失才回退挂单价。

## 20. 1 tick 宽盘口被 LP 机器人占位，挂单永远排不上

- **症状**：价差明明在、价格也对，挂单就是不成交（与 §1 的市场错位表现一样，极易误判成 bug）。
- **已修**：`book()` 增加 `bid1_size/ask1_size/lp_bot`，宽度 ≤1 tick 且两侧 ≥500 颗时打 `skip_lp_bot` 并跳过本轮 maker。

## 21. 每天几十轮小单把利润磨光

- **症状（潜在）**：单笔 20 颗、无轮次上限 → 笔数成本（排队损失、滑点、固定费）吃掉毛利；语料实证 495 笔 ≈ −3.4U。
- **已修**：`rounds_today()` + `config.max_rounds_per_day=12`，到上限停开新仓。

## 22. 成交价偏离无人监控（平台会替你做决定）

- **症状**：交易所风控/清算可以以远差于盘口的价格结束仓位且不报错（群内 Gate 把空单按 20% 拔高平掉）。
- **已修**：`spot_order()` 比对挂单价与成交均价，偏离 >0.3% 写 `fill_price_deviation` 并推送。

## 23. 把「统一账户显示 0」当成「没有保证金」

- 症状：`clearinghouseState.accountValue = 0.0`，据此判定无法开仓，并加了一道"保证金不足就不建仓"的闸。
- 真因：账户是**统一账户**（`userAbstraction=unifiedAccount`），现货 USDC 自动充当保证金；0 只是永续子账户的显示口径。实测远月挂单直接被接受。
- 代价：差点在价差达标时把能交易的账户锁死（比亏钱更糟）。
- 防复发：① `hl_margin()` 用 `avail = perp + (spot if unified)`；② 任何"余额/权限异常"的结论必须先做 0 成本探针（远月限价挂单 → 立即撤）；③ 台账此条永久保留。

## 24. 用「挂单价差」当信号，成交时吃的是卖一（虚高 0.68pp）

- 症状：日志报价差 1.50%，真成交只有 0.73%；整轮白亏 0.68pp。
- 真因：信号算 `(perp_bid − 现货买一)`，但下单必然吃卖一。回测用的是 `exec_spread`（= 永续买一 − 现货卖一），hedger 却用了挂单口径 → 计划与执行两套数。
- 代价：第一笔 100 颗在 0.73% 进场，把后续加仓的均价拖到 1.58%。
- 防复发：信号、回测、记账**统一** `(B买一 − A卖一)×2÷(两价之和)×100`；平仓方向同理用 `(B卖一 − A买一)`。

## 25. 部分成交后全额回滚（多付一次价差）

- 症状：现货买 25 颗成交，永续只成交 16.4 张；旧逻辑把 25 颗现货全部卖回 → 8.6 张空单裸露，再补回又付一次。
- 真因：`hl_order` 只返回 bool，调用方拿不到「成交了多少」。
- 防复发：`hl_order` 返回**实际成交数量**；部分成交只退回「现货 − 已对冲」的差额，剩下的照旧持有。

## 26. 平仓先卖现货、后买永续，中间出现裸腿

- 症状：平仓把现货卖掉一半，永续买回失败 → 裸空 50 颗（约 $76 名义）。
- 真因：`spot_trade` 在「复用已在途挂单」分支返回的 `filled` 不可信（挂单还没成交就报成交）。
- 防复发：① 卖出量只看**余额差**（`before − after`），不信回执；② 现货没真卖出就绝不先动永续；③ 主循环加对冲不变量 `|现货 − 永续| > 5` 立即纠正。

## 27. 权益自己加总，重复计算虚报 +$44.6

- 症状：`spotClearinghouseState` 的 USDC 已包含被 HIP-3 dex 占用的保证金，再叠加 `clearinghouseState(dex).accountValue` → 697.83，实际 650.33。
- 代价：一度以为当天赚了 $44，差点据此加仓。
- 防复发：权益只取 `POST /info {"type":"portfolio"}` 的 `allTime.accountValueHistory` 最后一点；换算一律以它为准。

## 28. fundingHistory 的比率当成逐小时实收（差 60 倍）

- 症状：仓库/对话里写「资费 0.94%/天 = $1.4/天」，实测 17:00 结算 `cumFunding.sinceChange = −0.000922`（名义 $148）→ −0.00062%/h。
- 真因：`fundingHistory` 的 `fundingRate` 与 `metaAndAssetCtxs(ctx).funding` 不是同一口径，不能乘 24 当收入。
- 防复发：资费只用 `ctx.funding`（下一期预估）或账户 `cumFunding` 实测；每小时写 `funding_log.jsonl` 累积真实值。

## 29. maker 优先在 1 tick 盘口等于没优先

- 实测：SafeTrade 挂单成交率 **22%**（100 笔里 22 笔 done），每口等 12–20 秒后仍吃单。
- 真因：`maker_sell_px = 卖一 − 1 tick`，在 1 tick 宽盘口下正好等于买一 → 等于主动吃单，还多等了 20 秒。
- 防复发：maker 只作为「省钱尝试」，等待时间压到 5 秒内；成交率低于 30% 就不指望它，成本按吃单算。

## 30. 平仓在烂盘口硬吃（把该赚的 0.6pp 送掉）

- 症状：两笔平仓的 `exit_edge_real` 都是 0.79–0.80，而当时盘口本来可以更好。
- 真因：止盈一触发就无脑吃买一，没有「吃单后还剩多少净利」的检查。
- 防复发：① 先在卖一挂单排队 25 秒；② 吃单前算 `(lot_edge − close_edge) − 0.29 ≥ min_net + 0.15`，不达标就继续挂；③ 现货盘口 >0.9% 时不平仓。
