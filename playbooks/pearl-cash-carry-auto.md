# PEARL 期现自动套利：执行方案 v1

> 标的：SafeTrade `PEARL/USDC|USDT` 现货 ↔ Hyperliquid `io:PRL` 永续（Entropy）
> 目标：捕获「永续溢价 − 现货折价」的收敛 + 空头资金费，全程自动、可随时停。

## 一、为什么是这个结构

- Entropy 是 HL 的 HIP-3 部署方（`perp_dex_index = 10`），`io:PRL` 资产号 **200010**，最大杠杆 **3x**，资金费 **+0.03%/h（年化 ~260%）→ 空头收费**。
- SafeTrade 现货长期相对永续折价（实测 21h 中位 +2.6%），但盘口薄：卖一 1% 内仅 **≈316 颗**。
- 三场所资金费全为正 → 只有「现货多 + 永续空」是收钱的一侧。期期配对是负期望。

## 二、硬约束（来自实测，不是估计）

| 项 | 值 | 影响 |
|---|---|---|
| 现货深度 | 卖一 1% 内 ≈316 颗 | **单轮 ≤300 颗** |
| 永续深度 | 买一 0.3% 内 ≈5,900 张 | 永续不是瓶颈 |
| 现货手续费 | maker/taker **0.1%** | 往返 0.2% |
| 永续手续费 | taker 0.009% | 往返 0.018% |
| 现货买卖价差 | ≈0.57% | 已在 entry/exit 口径内 |
| 最小名义 | 现货 2 颗；永续 $10 | 每档 ≥6 颗 |
| 价格刻度 | 0.01（现货）/ ≤5 有效数字（永续） | — |

**往返成本合计 ≈0.22%**（手续费）+ 已计入的买卖价差。

## 三、状态机

```
IDLE
 └ 可执行价差 ≥ 第1档阈值 且 深度 ≥ 0.5×下单量
     → OPEN_PERP（先空永续，IOC 限价，滑点 ≤0.15%）
         ├ 失败 → 放弃本轮，回 IDLE
         └ 成功 → OPEN_SPOT（SafeTrade 限价买，60s 未全成 → 撤余量）
              ├ 全成 → HEDGED
              └ 部分成/失败 → 立即按缺口平掉对应永续 → 回 IDLE
HEDGED
 ├ 价差 ≤ exit_spread（0.4%）= 收敛 → CLOSE_BOTH（先平永续，再卖现货）
 ├ funding < 0 连续 2 小时 → CLOSE_BOTH
 ├ 价差 ≥ stop_spread（3.5%）→ CLOSE_BOTH（认错）
 ├ 永续强平距离 < 30% → 减仓 50%
 └ 单腿偏差 > 2% → 补齐（自动对冲修复）
CLOSING → 校验双腿归零 → IDLE
```

**为什么先空永续**：永续深度好、成交确定；现货若买不到，平掉永续只损失 0.018% + 滑点。反过来先买现货，一旦空单没成交就是**裸多暴露**。

## 四、分档与上限

**目标仓位随价差分档（用户定的规则）：**

| 价差 | 目标持仓 | 保证金需求（3x） | 名义 |
|---|---|---|---|
| ≥1.5% | 100 颗 | ~$60 | ~$180 |
| ≥2.5% | 200 颗 | ~$120 | ~$360 |
| ≥3.5% | 300 颗 | ~$180 | ~$540 |
| ≥4.5% | 400 颗 | ~$240 | ~$720 |

- 每档之间每次只下 **20 颗**，间隔 **6 秒**（避免自己把盘口买穿）
- 硬上限：**400 颗 / $800 / 日亏 $30**（代码写死，config 改不动）
- 单次数量 = `min(20, 剩余目标, 0.5 × 卖一 1% 内深度)`，下限 6 颗
- 对冲按**币数 1:1**，不按金额
- 加仓前置条件：资金费 > 0 且 OI 5 分钟未掉 3%

## 五、止损：只设「意外止损」，不设「价格止损」

对冲仓的价格涨跌已经被两条腿互相抵消，**正常行情不该产生止损**。价差在 1%–6% 之间来回是常态（实测 ≥3% 占 37.8% 的时间），拿价差当止损会被正常波动反复打掉。

真正会亏钱的只有六类**意外**，止损就是针对意外：

| # | 意外 | 检测方式 | 自动动作 |
|---|---|---|---|
| 1 | 单腿没成交（裸多/裸空） | 双腿数量偏差 > 2 颗 | 立刻平掉多出的那条腿 |
| 2 | 现货报价过期/停牌 | 可执行价差 > 6%（异常宽） | 不进场；已持仓则暂停加仓 |
| 3 | 永续接近强平 | 距强平价 < 30% | 自动减半 |
| 4 | 资金费转负 | 连续 2 小时 funding < 0 | 全平（不给多头付钱） |
| 5 | 交易所/接口故障 | 连续 3 次调用失败 | 停手 + 报警，不平仓（先确认哪条腿在） |
| 6 | 跑路/关提币 | 人工判断 | `touch STOP` 一键停 |

账户级熔断（与行情无关，防连亏）：
- 当日实现亏损 ≥ **$20** → 停到次日
- 持仓超 **12 小时** → 强制平（避免结构变化后还占着保证金）
- 代码硬上限：**300 颗 / $600 / 日亏 $30**，配置文件改不动

原则：**任何异常先平腿、再报告，绝不带着单腿过夜。**

## 六、部署位置与组件

| 组件 | 位置 | 职责 |
|---|---|---|
| `exec.py` | 云机 systemd | 状态机主循环（5s） |
| 永续腿 | HL HTTPS + API 钱包 `0xE24C…` | 只可交易，不可提币 |
| 现货腿 | SafeTrade HMAC（经本机 Chrome 同源 fetch） | 只读+交易权限，无提币 |
| 行情/账本 | sqlite + jsonl | 每分钟快照、每笔操作留痕 |
| 看板 | Cloudflare Tunnel | 只读，含持仓/价差/PnL |
| 通知 | Telegram | 每笔开平 + 每日汇总 |

## 七、上线节奏

1. **纸面 12h**：`dry_run=true`，只记账不发单，核对信号与滑点假设
2. **$10 实弹**：永续开+平各一次，验证签名/成交/回执
3. **两腿小额**：一轮 100 颗（约 $180）
4. **放大**：数据达标后到 300 颗 / $600 上限

## 八、现实收益预期（按实测费率）

- 单轮：entry 1.2% → exit 0.4%，扣 0.22% 手续费 ≈ **+0.58%**
- 100 颗（$180 名义）≈ **$1.0/轮**；300 颗（$530）≈ **$3.1/轮**
- 资金费额外：持仓每小时 0.03%，一天满仓 ≈ **+0.7%/天**
- 机会频率：价差 ≥1.2% 的时间占比需 3 天数据确认；乐观 1–2 次/天

**结论：$600 上限下，日收益量级 $5–15，不是几百刀。** 想做大的唯一办法是加大本金，但 SafeTrade 深度会先被打穿。

## 九、未解决风险

1. SafeTrade 是小型交易所（24h 全站 $119K），**提币被关/跑路**是最大风险，不是价差
2. 资金费 +0.03%/h 属于高位，行情一转即变负
3. 现货历史深度只有快照，极端行情下盘口会瞬间抽空
4. `io:PRL` 3x 上限意味着保证金效率低，$530 名义需 $180+ 保证金
